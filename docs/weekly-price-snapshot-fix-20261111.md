## 관측 (GitHub Actions 로그, 운영 DB 미접속)

- 주간 실행 42239476808·42250612232(11월 6일 배치)은 `[1/6] KOSPI 벤치마크 조회`에서
  `publish_price_snapshot` RPC가 HTTP 400을 반환해 `model_failed`로 끝났다. KRX 준비도 검사나
  학습·품질 판정에는 도달하지 못했다. 42377500945는 지연 배달된 예약이 복구 시간대
  (금 16:12~토 18:00 KST) 밖이라 계획 단계에서 차단된 것으로 설계된 동작이다.
- 로그에 응답 본문이 없어 RPC의 어느 검증에 걸렸는지는 확정하지 못했다. 이 세션에서는
  Yahoo·Supabase에 접근할 수 없어 재현도 하지 못했다. RPC가 400을 내는 경로는 인자 오류,
  revision 충돌, 행 검증(`date`/`close` NULL, `close <= 0`, 날짜 중복)뿐이며, 첫 티커에서
  두 실행이 동일하게 실패했으므로 공급자 행이 저장 계약을 어긴 경우가 가장 유력하다.
- KRX 캐시는 11월 5일 이후 모든 실행이 `KRX_AUTH_FAILED`다. 예외가 아닌 로그인 거부이므로
  KRX가 응답했고 계정/비밀번호를 받아들이지 않은 것이다(코드로 해결 불가).
- Daily Auto Trade·추천 파이프라인 감시 실패는 유효 추천이 없어 생기는 후속 증상이다.

## 수정

- `scripts/price_store.py`: 공급자 응답을 비교·발행 전에 저장 계약으로 정규화한다. 시간대와
  시각을 제거해 거래소 달력 날짜로 맞추고, 종가가 유한 양수가 아닌 행과 같은 날짜의 중복 행
  (마지막 것 유지)을 제외하며 제외 건수를 출력한다. 이미 저장된 행은 여전히 덮어쓰지 않는다.
  벤치마크 최신 행이 제외되면 기준일이 하루 앞당겨질 뿐이고 4일 신선도 검사는 그대로다.
- RPC 실패 시 PostgREST의 `code`/`message`만 예외에 담는다(URL·`details`·행 내용 제외).
  다음 실패는 로그만으로 원인을 구분할 수 있다.
- `scripts/krx_cache.py`: 비밀번호 변경 요구를 `KRX_PASSWORD_CHANGE_REQUIRED`로 구분한다.
  공급자 출력은 고정 문구 포함 여부만 검사하고 출력하지 않는다.
- SQL 마이그레이션, 품질 기준, 주간 concurrency·복구 시간대는 변경하지 않았다.
