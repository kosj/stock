# 추천 종목 미표시 수정

2026-10-20 KST. 사용자 제보: 추천 종목이 보이지 않음.

## 원인

거래 안전성 변경에서 화면 API도 `recommendation_batches`만 조회하도록 바뀌었다.
기존 `prophet_recommendations` 이력은 남아 있어도 완료 메타데이터가 없으면 표시되지 않았다.
직전 운영 DB 점검에서 완료 배치는 0건, 추천 이력은 10,234행이었다.
이 API는 `.single()`로 빈 결과를 오류로 취급했으며 UI fetcher는 HTTP 오류도
정상 JSON으로 받아 오류를 '분석 결과 없음'과 구분하지 못했다.

이번 GitHub 실행 이력 조회에서도 마지막 추천 작업은 10월 16일이었다.
주간 스케줄 전환 후 첫 금요일은 10월 23일이다. 완료 배치가 없다는 것이 곧
새 모델 품질 게이트 실패를 의미하지는 않는다. 수정된 전체 학습은 아직 실행하지 않았다.

## 수정

- 완료 메타데이터가 없으면 기존 순위 이력을 화면에서만 조회한다.
  응답은 `status: legacy_unverified`, `verified_batch: false`, `return_calibrated: false`.
- UI에 기준일과 '과거 결과·새 품질 검증 미완료·자동매매 미사용' 안내를 표시한다.
  과거 결과를 현재 매수 신호로 표현하지 않는다.
- 완료 배치가 있다면 이전처럼 우선 표시한다. 명시적 날짜 조회도 같은 규칙이다.
- `.maybeSingle()`로 정상적인 빈 결과를 처리한다. DB 오류는 503으로 반환하고
  UI에서 오류·빈 목록·불완전 배치 상태를 구분한다.
- 저장된 Top20의 순위/티커 유일성·가격을 확인해 부분 목록은 표시하지 않는다.
- 자동매매 adapter/품질 게이트/완료 메타데이터는 변경하지 않았다. 이력 승격 없음.
- 주간 workflow 중복 방지는 개별 추천 행 대신 완료 배치 존재 여부를 확인한다.
  불완전/레거시 행 때문에 정상 발행 재시도가 생략되지 않게 한다.
- 모니터는 화면용 과거 이력을 신규 발행 성공으로 간주하지 않는다.

## 검증 및 한계

Node 전체 70개 테스트, 타입 검사, 프로덕션 빌드, 마이그레이션 감사가 통과했다.
lint는 기존 59개이며 신규 위반은 없다.

실제 GET 핸들러를 사용한 격리 회귀 테스트 6개:
과거 이력 복원, 완료 배치 우선, 빈 DB, 조회 실패, 날짜 필터/잘못된 날짜,
불완전/중복/가격 결손 목록 거부를 확인했다.

현재 클라우드 세션에는 이전 Supabase CLI 로그인과 앱 승인 세션이 남아 있지 않았다.
읽기 전용 SQL 재조회는 LoginRequired로 실패했으며 비로그인 운영 API는 401이다.
따라서 이번 세션의 운영 이력 행 수 재조회나 승인 사용자 브라우저 검증은 수행하지 못했다.
운영 DB에 쓰기 요청, 추천 발행/모델 학습, 주문 호출은 하지 않았다.
