# 브라우저 키 및 KIS 조회 변경 (2026-10-20)

## 구현

- `frontend/lib/apiConfig.ts`가 로드되거나 기존 호환 메서드를 호출하면 localStorage와
  sessionStorage의 구형 마스터 비밀번호/해시, 증권사 설정, KIS 토큰,
  Anthropic/FRED 키를 삭제한다. 암호화된 증권사 설정 옆에 복호화 비밀번호를 저장하던 경로를 없앴다.
- 증권사 키는 승인된 계정의 `/api/settings/broker`에서 서버 AES-256-GCM 암호화 저장만 지원한다.
  구형 브라우저 설정을 자동 복호화/이전하지 않는다. 사용자는 설정에서 키를 다시 등록한다.
- Anthropic/FRED 선택 키는 현재 탭 메모리만 사용한다. 새로고침과 UI 로그아웃에서 지워진다.
  브라우저의 디스크 저장소로 복구/복사하지 않는다.
- `kis-browser.ts`는 인증된 Next.js 보유종목 경로를 호출하는 호환 래퍼다.
  브라우저가 KIS 토큰을 발급하거나 저장하지 않는다. broker quote/indices도 서버 저장 키만 사용한다.
- 설정에서 KIS 실전/모의투자 환경을 키와 함께 저장한다. 모의 환경은 `openapivts:29443`,
  실전 환경은 `openapi:9443`으로 나뉜다. 잔고 요청 본문으로 저장된 환경을 바꾸지 못한다.
- 서버 토큰 캐시는 사용자/환경/전체 키/비밀키/계좌를 SHA-256으로 묶는다.
  최대 256개, 5분 전 갱신, 동시 토큰 발급 합치기, 실패 후 재시도 기능을 갖춘다.
  **같은 서버 인스턴스 안의 최적화**다. 서로 다른 서버리스 인스턴스의 발급 요청은 합치지 않는다.
- 잔고 연속조회는 공식 KIS 예제의 F/M 응답, `tr_cont=N`, FK/NK 커서를 따른다.
  최대 20페이지, 커서 누락/반복/한도 초과는 부분 잔고를 반환하지 않고 실패한다.
  공식 참고: https://github.com/koreainvestment/open-trading-api/blob/main/examples_llm/domestic_stock/inquire_balance/inquire_balance.py
- Axios 오류에는 자격증명이 포함될 수 있으므로 KIS 오류 객체를 로그에 출력하지 않는다.

## 푸시 알림 상태

Next.js에는 사용자별 푸시 발송 워커가 없다. 이전 구독 API는 아무것도 저장하지 않고 성공을 반환했다.
이제 승인된 사용자의 구독 요청에도 501을 반환하며, UI는 발송 기능 준비 중으로 표시한다.
브라우저 알림 허용만으로 푸시 활성화가 되었다고 표시하지 않는다.
가격 알림 조건 저장은 유지된다. 실제 발송 구현은 별도 작업이다.

## 운영 적용 및 남은 일

- 코드 반영만으로 기존 배포된 Edge Function이 바뀌지 않는다. 구형 `kis-holdings`를 삭제하거나
  이번 410 응답 구현을 배포해야 익명 프록시가 닫힌다. 이번 작업에서는 배포하지 않았다.
- 서버에는 유효한 `BROKER_ENCRYPTION_KEY`(64자리 hex)와 Supabase service role이 필요하다.
- 기존 브라우저 저장 키가 노출되었는지 확인할 수 없다. 브라우저 정리는 과거 유출을 되돌리지 않는다.
- 실제 KIS 호출/잔고 조회, 외부 서비스 키 검사, 운영 DB 쓰기는 하지 않았다.
- 실제 다중 페이지 계좌/실전·모의 응답 확인, 배포 인스턴스 간 토큰 조율 필요 여부는 운영 확인 대상이다.
- 자동매매 실전 주문 어댑터를 추가한 것이 아니다. 기존 실전 주문 차단 정책을 유지한다.
