# 계좌 통합 검증·실자료 진단·포트폴리오 수정

2026-10-20 KST 후속 작업. 이전 문서 커밋 `62400aa`까지 GitHub CI와 배포 성공을 확인하고 시작했다.
실제 주문·계좌 초기화·포트폴리오 교체를 운영에서 테스트하지 않았다.

## 이번에 수정한 문제

### 증권사 보유종목 가져오기 중 데이터 손실

기존 UI는 저장된 종목을 먼저 삭제하고 새 종목을 병렬로 개별 저장했다.
일부 저장 실패 시 기존 목록이 사라진 채 일부만 남을 수 있었다.

- `POST /api/portfolio/[id]/positions/replace`와 서비스 역할 전용
  `replace_portfolio_positions(uuid,bigint,jsonb)` RPC로 한 트랜잭션에서 교체한다.
- 승인 사용자와 DB 소유권을 확인하고 전체 입력을 검증한 후 삭제/삽입한다.
  최대 200개/64KiB, 중복 티커·잘못된 수량·가격·필드 등을 거부한다.
- 삽입 중 실패하면 기존 종목과 연결된 알림까지 롤백한다.
- 응답 유실은 커밋 여부가 불명확할 수 있으므로 실패를 곧바로 롤백이라고 표현하지 않는다.
  UI는 선택을 유지하고 서버 목록을 재조회하여 확인한다. 구형 삭제/추가 경로로 폴백하지 않는다.
- 실제 동작에 맞게 '교체'라고 표시하고, 기존 메모·손절·목표가 교체를 안내한다.
- 별도의 빈 계좌 자동 동기화는 기존 추가 방식을 유지하며 부분 성공·실패 건수를 정확히 알린다.
  별도 편집/세션과 동시 변경을 막는 revision 계약까지 새로 도입한 것은 아니다.

### 수정 직후 합계 및 리플레이 평가

- 포트폴리오 수량·평균단가 수정 후 장부금액·평가금액·손익을 즉시 다시 계산한다.
- 리플레이에서 시세 결손 때 평단으로 평가해 기존 평가손익이 갑자기 사라지는 문제를 수정했다.
  마지막 실제 관측 시세를 평가에만 이월하고 stale 표시를 유지한다. 매매에는 사용할 수 없다.
- `valuationComplete`/`finalValuationComplete`로 결손 평가가 있는 잠정 성과를 구분한다.
- 타임존·시각이 없는 입력, 존재하지 않는 날짜, 중복/역순 세션과 누락된 비용 필드를 거부한다.

## 격리 검증

- 실제 인증 가드·계좌/주문/초기화/로그 핸들러와 PGlite SQL RPC를 연결한 계좌 테스트 7개.
- 원자적 가져오기 테스트 8개: 소유권·권한·전체 입력 거부·삽입 후 강제 실패 롤백·응답 유실 등.
- 리플레이 안전성 3개, 포트폴리오 계산 3개 추가.
- 전체 Node 테스트 64개, Python 18개, 뉴스 검사 전체 통과. 타입 검사 및 빌드 통과.
- 브라우저·실제 세션 발급·실제 공급자 시세를 포함한 staging E2E와는 다르다.

포트폴리오 타입/오류 처리와 차트 타입을 정리해 실제 lint 위반을 **108개에서 59개로** 줄였다.
새 위반은 없으며 기준선도 현재 59개로 낮춰 같은 오류의 재유입을 차단한다.

## 실제 추천 이력 진단

추천 10,234행과 저장 종가 114,422행을 읽기 전용으로 추출해 파일 기반 진단을 수행했다.
자세한 집계/입력 SHA256/한계는 [실자료 보고서](recommendation-diagnostics-20261020.md)와
동명 JSON을 참조한다. 원시 추출본은 시장/추천 정보뿐이며 GitHub에 대량 복사하지 않았다.

Top5의 1·5·10·20세션 KOSPI 대비 평균 초과수익은 +0.028/+0.158/+0.130/+1.120%p였지만
Newey-West t는 0.090/0.148/0.068/0.332로 통계적 우위를 뒷받침하지 않는다.
이는 비용 전, 중첩된 코호트 평균이며 누적 계좌 수익이 아니다. 신규 코드의 성과도 아니다.
주말 기준일 중복, 미성숙 라벨, 실제 진입 종가보다 늦은 생성, 정확한 가격 결손을 처리했다.
기존 백테스트의 중첩 알파 합계를 '누적 수익률'로 표시하던 부분도 제거했다.
이 자료만으로 가중치/손절 기준을 조정하지 않았다.

운영 `recommendation_batches`는 읽기 점검 시 **0건**이었다. 검증 완료 배치가 없어 신규 자동매수가
보류되는 안전장치를 유지했다. 기존 추천을 임의로 완료 배치로 승격하지 않았다. 최초 품질 게이트
통과 배치 생성과 실제 시점 데이터 누적이 필요하며, 손절 검사와 신규 매수 가능 여부는 구분한다.

## DB 적용

새 전진 마이그레이션 `202610200006_portfolio_import.sql`을 격리 검증 후 Supabase CLI로 적용했다.
기존 11개 SQL은 변경하지 않았다. 이력 등록과 함수 정의는 동일 트랜잭션으로 처리했고,
원격 12개 SQL 본문이 모두 로컬 파일과 일치함을 확인했다. rollout 해시 기록을 갱신했다.
신규 함수는 anon/authenticated 실행 불가, service_role 실행 가능을 재확인했다.
운영 포트폴리오 2개·포지션 4개를 변경하지 않았고, 새 교체 RPC는 운영에서 호출하지 않았다.

## 원격 CI에서 발견한 소스 누락

첫 원격 검사에서 새 통합 테스트가 자동매매 로그 라우트 파일 누락을 발견했다.
로컬에는 있었지만 기존 `.gitignore`의 `logs/` 규칙으로 커밋에 포함되지 않았던 파일이다.
API 소스의 logs 디렉터리/route.ts만 예외로 추가하고 실제 라우트를 추적하도록 수정했다.
이 경우 배포는 CI에서 차단됐으며, 운영 사용자 세션을 시험에 쓰지 않고 누락을 확인했다.
