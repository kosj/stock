# 모델·데이터 병렬 개선 인수인계

2026-10-19 작업. 운영 API/DB 접근, 전체 학습, 실제 성과 측정은 실행하지 않았다.

## 반영 내용

- ALG-01: 추천 진단 백테스트가 `run_date,ticker` 순서로 페이지를 끝까지 읽는다.
  요청 한도보다 작은 서버 페이지도 실제 수신 건수로 다음 offset을 계산한다.
  `lag=1`은 기준일 다음 첫 거래일로 정의하여 주말·휴일 기준일의 하루 밀림을 제거했다.
  이 도구는 종가 진입 추천 품질 진단이며 운영 09:12 체결 전략 성과가 아니다.
- ALG-03: ETF 앱과 스냅샷의 동률 값에 평균 순위를 적용했다. 같은 신호는 같은 점수이며
  입력 순서가 임의 점수 차이를 만들지 않는다. 두 구현의 일치 회귀 테스트를 추가했다.
- ALG-04: RSI의 상승 구간은 100, 하락 구간은 0, 보합 구간은 50이다.
  최초 14개 관측치의 준비 기간 결측은 그대로 유지한다.
- PERF-03: ETF 전체 순위는 정규화한 기간/계좌/필터별로 30초 캐시하며 동일 요청의
  진행 중 작업을 공유한다. 완료 캐시와 진행 중 키는 각각 최대 32개로 제한한다.
  서로 다른 요청도 같은 프로세스에서 차트 조회 동시 8개·대기 256개 한도를 공유한다.
  캐시는 조회 화면 전용이며 실행 가능한 체결 시세로 사용하지 않는다. 서버 인스턴스별
  한도이므로 전체 배포의 전역 API 사용량을 제한하려면 외부 공유 조정기가 필요하다.
- ALG-05: 가격 저장을 단일 DB 읽기/발행 RPC로 교체했다. 전체 시계열과 revision을
  같은 SQL 스냅샷으로 읽고, 발행은 revision 비교 및 티커 잠금 아래 원자적으로 수행한다.
  이전 저장본은 revision 0, 이후 발행본은 새 revision으로 보존한다.
  삭제 후 청크 적재 방식과 부분 적재를 성공처럼 처리하는 경로를 제거했다.
  설정된 DB 접근/발행 실패 또는 동시 쓰기 충돌은 학습을 중단한다.
  추천 `accuracy_json`에 종목/벤치마크 가격 revision과 PIT 유니버스 미구현 상태를 기록한다.

## 적용 전제

- 기존 `20260816_price_daily.sql` 적용 후
  `202610200003_price_versions.sql`을 적용해야 새 가격 저장 코드를 사용할 수 있다.
  기존 마이그레이션 버전 중복 이력을 먼저 확인한다. 이 작업에서 원격 적용하지 않았다.
- RPC와 버전 테이블은 service_role 전용이다. 프런트에 서비스 키를 노출하지 않는다.
- `price_daily`는 기존 조회자의 호환 테이블로 유지된다. 다른 적재기가 직접 이 테이블을
  수정하면 revision 계약을 우회한다. 새 적재기는 반드시 발행 RPC를 사용해야 한다.
- 버전 이력은 전체 행을 보관하므로 DB 용량이 증가한다. 보존 기간/저장 비용 정책은
  재현에 필요한 입력을 삭제하지 않도록 운영 데이터 규모 확인 후 정해야 한다.
- 가격만 버전 관리한다. 수급·재무·뉴스·감성·유니버스의 시점별 원본을 모두 고정한
  완전한 학습 입력 재현성은 아직 제공하지 않는다.
