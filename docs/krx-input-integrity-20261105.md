# KRX 수급·밸류 갱신 장애와 입력 검증 — 2026-11-05

운영 읽기 전용 조회에서 krx_daily 91개 종목의 최신 일자가 2026-09-10~11로 확인됐다.
11월 4일 실행 41851727003은 로그인 실패를 반복하고 0/91종목·0행을 적재했는데도 성공
종료했다. 이는 10월 30일 품질 미달의 유일한 원인으로 확정할 수는 없지만 최근 입력의
관측 부족을 중립값으로 숨기는 문제다. KIS 개인 시세 키와 KRX 공급자 계정은 별개다.

## 수정과 검증 경계

- 공식 pykrx v1.2.8의 인증 세션 API를 확인하고 버전을 고정했다. 로그인 preflight가
  실패하면 공급자 조회·적재 전에 중단하며 출력에는 키·계정명·응답 본문을 내보내지 않는다.
  버전 고정 자체로 인증 실패가 해결된다고 주장하지 않는다.
- 기존 7일 적재 범위를 종목별 마지막 완전한 캐시 날짜 이전까지 자동 확대한다. 캐시가
  없으면 기존 5년 백필 범위를 사용한다. 명시적 --backfill도 유지한다. 9월 이후 공백을
  최근 7일만 채워 숨기는 것을 방지하며 기존 캐시를 삭제하지 않는다.
- 부분 필드·NaN/무한값·오래된/미래 원본은 적재하지 않는다. HTTP 적재 실패와 0행·일부
  종목 누락은 실패다. 전체 적재는 단일 트랜잭션이 아니므로 실패 전 완료한 종목은 보존되며
  다음 실행에서 멱등 upsert로 재시도한다.
- 운영 추천은 각 종목의 최근 20개 실제 가격 관측일(가장 긴 수급 피처 기간)에 4개 필드가
  모두 유한값으로 존재해야 사용한다. 미달 종목은 제외하고, 유효 종목이 20개보다 적으면
  학습·발행을 중단한다. 과거 시점 재무정보나 전체 과거 유니버스의 정합성을 증명하지 않는다.
- 모델 품질 기준 IC >=0.01, NW t >=2, 평가일 >=60은 유지한다. 자료 복구만으로 품질 통과나
  추천 발행이 보장되는 것은 아니다. 주간 concurrency·복구 시간·기존 영수증 검증도 유지한다.
- 캐시 loader 관련 변경을 master에 배포하면 캐시 워크플로가 자동 실행되도록 하며 수동 및
  예약 실행과 같은 concurrency를 사용한다. 운영 데이터 적재는 사용자 요청의 복구 범위다.
  테스트에는 가짜 공급자·HTTP만 사용한다. 추천/계좌/거래 이력을 검증용으로 수정하지 않는다.

## 아직 필요한 운영 증거

수정된 캐시 Actions에서 인증·비어 있지 않은 완전한 원본·실제 적재를 확인하고, 읽기 전용
DB 조회로 날짜와 공백을 재확인해야 한다. 인증이 계속 실패하면 소유자가 KRX 사이트에서
계정 로그인 가능 여부와 비밀번호 변경 요구를 확인하고 GitHub의 KRX_ID/KRX_PW를 갱신해야
한다. 실행 환경의 공급자 접근 제한 가능성도 있으며 암호를 추측하거나 인증을 우회하지 않는다.
정상화 전에는 새 추천이 정상 발행된 것으로 보고하지 않는다.
