# 시점 증거 기반 오프라인 전략 비교 — 2026-10-31

## 범위와 상태

`npm run backtest:compare -- comparison.json`은 기존 운영 공통 엔진을 두 번 이상
오프라인 실행한다. 기존 전략, 품질 기준, DB, 인증, 거래 API 및 예약을 변경하지 않는다.
동일 시작금·자본한도·거래비용·시세/지수 관측·섹터 한도와 동일 유니버스 증거를
요구한다. 추천 결과만 서로 다르게 만들어 비교할 수 있다. 실제 시점 자료를 확보하거나
과거 가격·종목군을 복원한 것은 아니며 실측 성과 또는 모델 개선 증거도 아니다.

이 도구는 **사용자가 제출한 출처와 시각의 논리적 일관성만 확인한다.** 스냅샷의 진위,
유니버스의 전체성과 상장폐지 포함 여부, 과거 기업행위 및 공시 시점, 모델 학습과
피처의 시점 정합성, 기록한 연구 질문·판정 규칙의 사전 등록 여부를 증명하지 못한다.
출력의 `evidenceStatus`는 항상 `declared_not_independently_verified`이며 결과는
탐색적이다. 수익률이 높다는 이유로 자동 승격하지 않는다.

## 입력 계약

JSON 루트는 `researchQuestion`, `predeclaredDecisionRule`, `variants`다. 각 variant는
고유 `id`, 기존 `ReplayInput`인 `input`, `evidence`를 갖는다. 기존 형식과 실행 전제는
[리플레이 설명](trading-safety-handoff.md)을 참조한다. 시각은 시간대를 포함해야 한다.

- `input.costs`에 `feeRate`, `sellTaxRate`, `slippageRate`를 모두 명시한다.
  세금 0도 입력 가정일 뿐 면세 판정이 아니다. 공통 세율이고 실제 종목별 세율은 미지원.
- `evidence.sourceDescription`: 보관된 원천의 설명. 비밀키나 개인정보 금지.
- `evidence.sessions`: `input.sessions`와 같은 순서·길이. 각 항목은 `at`과
  `prices`를 갖고, 가격 맵의 각 ticker에 `{sourceId, observedAt, availableAt}`을 둔다.
  지수 가격이 있으면 같은 형태의 `benchmark`도 필요하다. 관측 <= 입수 <= 세션 시각.
- `evidence.batches`: 배치와 같은 순서·길이. 각 항목은 `completedAt`,
  `universeSnapshotId`, `universeObservedAt`, `universeAvailableAt`, `universeTickers`를
  갖는다. 각 추천 종목은 선언된 유니버스에 있어야 하며, 유니버스 입수는 배치 완료
  이전이어야 한다. 이 검사는 모델이 그 시점의 유니버스를 실제 사용했는지 증명하지 않는다.
- 각 variant의 세션 증거와 배치별 유니버스 증거도 동일해야 한다. 서로 다른 평가 기간,
  비용 또는 관측치를 가진 결과를 같은 조건의 실험으로 오인하지 않기 위한 제약이다.
- `sourceId`는 원본을 독립적으로 재확인할 수 있는 비밀이 아닌 식별자여야 한다.
  월별 종목군·상폐·공시·가격 수정 이력은 별도로 확보하고 원천의 무결성을 검증한다.

출력은 각 variant의 완전한 기존 리플레이 결과, 비용, 체결, 평가 완전성 및 한계를 포함한다.
벤치마크는 전 세션에 유효한 값이 있을 때만 비교된다. 평가에 오래된 가격이 하나라도
사용되면 `valuationComplete=false`; 이때 표시된 성과는 잠정치다. 같은 관측을 썼더라도
호가·시장 충격·휴일·거래 불능은 충분히 재현하지 못한다. 원본 자료가 없으면 생성하거나
종가를 장 시작 시각의 가격으로 임의 대체하지 않는다.

## 후속 단계

1. 독립적으로 검증 가능한 과거 시점 유니버스, 추천 발행 시각, 장중 가격·지수 및 해당
   세율 자료 확보. 입수 불가능한 구간과 가격 수정·기업행위 범위를 명시한다.
2. 기존 혼합 점수·모델 단독·감성 제외 등의 후보를 동일 시점에 재현할 수 있는 입력과
   사전 확정된 실험 계획을 만든다. 실제 과거 중간 점수가 없다면 소급 추정하지 않는다.
3. 장기간 walk-forward, 거래비용 민감도, 단순 기준 전략, 독립된 최종 구간 및
   다중 시험을 고려한 불확실성 평가를 실행한다. 현재 도구는 통계적 신뢰구간을 계산하지 않는다.
4. 확인된 자료와 결과에 근거해 재무·공시 피처를 추가하고 시점 테스트 및 별도 표본 외
   검증을 수행한다. 데이터가 준비되지 않았는데 실거래 정책, 모델 가중치, 손절 또는
   발행 품질 기준을 조정하지 않는다.

추가 한계: 리플레이는 각 입력 세션에서 일반 거래 엔진을 호출한다. 별도로 예약되는
장중 risk-only 실행을 실제 운영 스케줄 그대로 재현하지 않는다. 각 세션을 장중 손절
전용으로 간주하거나 정확한 운영 손절·매수 빈도를 추정하면 안 된다.
