# 모의투자 체결·위험 점검·성과 기록 수정

2026-10-31 KST. 기존 손익 부진 점검에서 확인한 우선순위에 따라 구현했다.
수익률을 높였다는 실측 결과가 아니라 체결 가능성·장애 탐지·집중도·성과 측정의 수정이다.
모델 품질 기준(IC >= 0.01, NW t >= 2, 평가일 >= 60)과 실거래 비활성 상태는 유지한다.

## 1. 실제 관측 시각이 있는 체결용 시세

- `ExecutionMarketDataAdapter`가 해당 사용자의 암호화된 KIS 설정을 서버에서 읽는다.
  계좌별 자격증명을 다른 사용자와 공유하지 않고 토큰 캐시에도 사용자 scope를 유지한다.
- KIS의 **읽기 전용** 주식/지수 분봉 API를 사용한다. 실전/모의 API 환경 선택은 저장된
  `isDemo` 설정을 따른다. 어떤 경로에도 KIS 주문 API를 추가하지 않았다.
- 각 행의 `stck_bsop_date`와 `stck_cntg_hour`를 함께 검증하고 가장 최근 유효 관측을 고른다.
  날짜 누락을 오늘 날짜로 채우거나 HTTP 시각을 실제 거래 시각으로 바꾸지 않는다.
  기존 10분 신선도·최대 1분 미래 오차·양수 유한 가격 검증을 유지한다.
- KIS가 없거나 실패하면 Yahoo의 **기존 신선도 검증을 통과한** 값만 대체할 수 있다.
  국내 Yahoo 시세는 공식 안내상 20분 지연이므로, 키가 없는 계정의 정상 체결을 보장하지 않는다.
  설정/요청 실패/유효 관측 없음/시간 예산 초과를 정적 코드로 구분한다.
- 같은 요청에서 broker와 sizing이 동일 adapter를 사용한다. 관측은 요청 내 30초만 재사용하며
  매번 거래 시각을 다시 확인한다. KIS 요청을 550ms 간격으로 직렬화하고 25초의 공급자 조회
  예산을 둔다. 공급자 장애로 서버리스 실행을 무한 대기시키지 않는다.
- 수동 모의주문도 같은 체결 시세 경로를 사용하며, 주문 UUID·계좌 세대·서버 인증을 유지한다.

## 2. 장애와 정상 보유 유지 구분

기존에는 모든 보유 종목이 시세 누락으로 SKIP이어도 `error`가 없어 daily job을 done으로
기록했다. 이제 시세 장애는 `QUOTE_UNAVAILABLE`, `degraded`, 미완료 risk check와 오류로
반환한다. 위험 점검에서 확인한 계정의 실제 데이터 부족을 정상 무거래와 혼동하지 않는다.
기존 일일 작업 큐는 이 오류를 기존 최대 3회·30초 지연 정책으로 처리한다.
로그에는 HTTP 요청 객체·서명 URL·인증 헤더를 저장하지 않는다.
수동 자동매매 API도 승인 사용자 가드를 적용하고 실패 결과를 HTTP 503으로 표시한다.

## 3. 장중 손절 전용 점검

`.github/workflows/intraday-mock-risk.yml`은 평일 KST 09:02부터 5분 간격의 best-effort 예약이다.
서버는 09:00~15:30 밖을 거부한다. GitHub 지연/누락 가능성은 남으므로 -5% 체결가격을
보장하는 손절 시스템이나 정시 SLA로 표현하면 안 된다.

인증된 `POST /api/cron/mock-risk`는 승인된 mock 계정만 읽기 전용 RPC로 조회한다.
전용 경로는 서버 내부에서 risk 모드를 강제한다. 구버전 서버에서는 404로 중단되므로
배포 지연/롤백 때 기존 일반 자동매매 endpoint가 risk 인자를 무시하고 매수하는 것을 막는다.
페이지 cursor와 사용자별 처리 결과를 반환하며, 시간/페이지 예산과 실패 알림을 둔다.
**이 모드는 추천 순위 조회·랭크아웃 청산·신규 매수를 하지 않는다.** 기존 공통 엔진에서
손절만 수행하고 일일 리밸런싱과 동일한 계좌 lease/epoch/당일 주문 키를 사용한다.
같은 종목의 반복 손절 체결이나 일일 매매와의 동시 실행은 기존 영속 guard가 막는다.

## 4. 실제 계좌 금액 기준 집중도

신규 매수 예산에 종목당 25%, 섹터당 50% 상한을 적용한다. 이는 과거 손익에 맞춰 탐색한
최적 비중이 아니라 위험 한도이며, 수익 개선을 보장하지 않는다. 운영 설정은
`MOCK_MAX_POSITION_WEIGHT`/`MOCK_MAX_SECTOR_WEIGHT`의 0 초과 1 이하 비율이다.

기준 자본은 `min(계좌 현금 + 실제 보유 평가액, 설정된 자동매매 자본)`이다. 수수료·슬리피지가
포함된 신규 체결 금액도 섹터 예산에서 차감한다. 보유 종목을 포함해 실제 금액을 합산하므로
Top20의 섹터별 종목 수 제한만 두던 문제를 막는다. 이미 한도를 넘은 보유를 강제 매도하지 않는다.
보유/후보 섹터가 불명확하면 신규 매수를 보류하되 유효한 시세의 손절 검사는 계속한다.
Top20 밖의 보유 종목도 최신 완료 배치 전체의 sector를 조회한다.

공통 엔진 리플레이도 같은 한도를 적용한다. `ReplayInput.exposureLimits`로 명시한 정책을
비교하고, `ReplayBatch.sectors`에 해당 당시 전체 배치의 티커→섹터 매핑을 제공할 수 있다.
없는 섹터/과거 체결 가능 시세를 사후 추정해서 채우지 않는다. 기존 정규장 외 체결 이력을
현행 전략 성과로 승격하거나 이 자료에 맞춰 손절·모델 가중치를 최적화하지 않았다.

## 5. 관측 평가액과 입출금 기반 성과

- 실제 실행 후 lease 안에서 계좌 세대·보유 수량과 일치하는 평가 관측을 별도 테이블에
  추가한다. 기존 장부 기준선·잔고·보유·체결·입출금 이력을 재작성하지 않는다.
- 가격/실제 관측 시각이 빠지거나 오래된 평가는 `complete=false`, `equity=null`이다.
  평단으로 평가손익을 0으로 만든 뒤 신뢰할 수 있는 수익률처럼 기록하지 않는다.
- 관측은 불변이며 같은 사용자·계좌 세대·관측 시각의 재시도로 덮어쓰지 않는다.
  전략 버전, 모드, 추천 기준일/모델 버전, 손절·순위·집중도 정책도 함께 기록한다.
- 성과는 현재 epoch의 첫 실제 완료 관측부터 최신 관측까지 계산한다. 입출금 시각을
  반영한 **Modified Dietz**를 사용한다. 입출금 직전 평가가 없는 상황에서 정확한 TWR이라고
  표시하지 않는다. 관측 2개 미만/최신 평가 미완료/유효 투자금 없음은 산정 보류다.
- KOSPI 분봉 관측과 보유 가격의 시각이 ±60초 이내로 맞는 양끝에서만 벤치마크를 비교한다.
  기간 내 입출금이 있으면 동일 흐름을 반영한 벤치마크 경로가 없으므로 초과수익률을 보류한다.
- 화면에서 기존 값은 '장부 기준 손익', 새 값은 '관측기간 수익률'로 구분한다.
  기존 장부 값은 최초 투자 이후 전체 수익률이나 기준선 날짜 이후의 기간 수익률이 아니다.

## DB 적용 및 보존 확인

격리 PostgreSQL에서 신규 DDL/RPC/권한을 검증한 뒤 연결된 기존 프로젝트에 다음 두 전진
마이그레이션을 적용했다. 기존 적용 SQL 본문은 변경하지 않았다.

| 버전 | 변경 |
|---|---|
| 20261031000529 | 성과 관측 저장·조회 RPC, news_sentiment RLS 및 공개 역할 권한 차단 |
| 20261031000539 | 서비스 역할 전용 승인 mock 계정 조회 RPC |

원격 14개 migration의 저장 본문 MD5가 로컬 파일 바이트와 모두 일치함을 재조회하고,
실제 적용된 파일의 SHA256만 `verified-rollout.json`에 기록했다. 적용 전후 계좌·보유·체결·
현금 원장·추천·배치·감성 데이터 7개 테이블의 행 수와 전체 행 해시가 동일했다.
감성 테이블 권한 검사에서 anon/authenticated 쓰기는 false, service_role 쓰기는 true였다.
성과 테이블은 비어 있고 실제 계좌의 쓰기 RPC/손절·매수/초기화/모델 학습을 검증용으로
실행하지 않았다. 보안 advisor의 news_sentiment RLS 비활성 오류도 사라졌다.

## 검증 및 적용 후 조건

- 신규 20개 검사: 실제 KIS parser/provider/router, 공급자 오류 비밀키 비노출, risk-only
  엔진·실제 cron 핸들러, 집중도·입출금 성과, snapshot 소유권·epoch·불완전 평가·RLS,
  승인 계정 pagination과 현재 역할 재확인. 모두 가짜 HTTP/격리 DB를 사용한다.
- 전체 `npm run test:safety`, 타입 검사, lint 회귀 검사, migration 감사 및 actionlint를 실행한다.
  최종 GitHub CI 링크는 PR에 기록한다.
- 배포 후 각 계정에 서버 저장 KIS AppKey/AppSecret 설정이 필요하다. 실전 API 환경의
  시세 조회 키를 사용해도 이 앱의 실거래 주문 기능이 활성화되는 것은 아니다.
- 10월 31일은 토요일이다. 장중 공급자 가용성·실제 허용량·분봉 도착 시각을 포함한
  운영 E2E는 다음 정규장에서 확인해야 한다. 키가 없거나 검증을 통과하지 못하면 계속
  명시적으로 보류한다. 20분 지연 Yahoo나 조회 시각으로 체결을 강제하지 않는다.
- 새 신뢰 가능한 성과는 배포 후 실제 관측부터 누적된다. 과거 수익률을 고쳐 보이게 하거나
  초기화해 손실을 숨기지 않는다. 기존 모델 품질 미달에 따른 발행 보류도 유지한다.
